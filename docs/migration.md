# 安装、迁移与回退

先在隔离目录安装发行tgz并运行测试。保留宿主提供的Cordis/tools/scope实例，避免多份scope单例。生产运行以DSH 0.2.1-rc.2、Node24为验证组合。

本版本要求经过QQ生命周期隔离验证的Mnemon套件；原版Mnemon仅开启全局记忆不能替代该验证。配置须指定兼容的`mnemonModuleRoot`与数据目录，必须排除`qq-yuzu`、`qq-report`及其后代的通用召回、投影和后台维护。缺失适配时插件拒绝启用推理，不回落到全局记忆。已有角色、AGENTS、记忆来源权限应保持。

1. 记录实际服务、源配置、profile、会话映射与业务库基线。仅在获得该项目备份授权时备份专用配置、SQLite一致性快照和业务数据。
2. 在独立profile校验新包，使用假的OneBot/模型做流程验证。核对最终模型菜单和执行守卫，包括在agent自身scope动态注册的服务器工具。
3. 停止旧消费者，再启用新插件。两个消费者不能同时监听回复。保留原QQ网关登录，不重建QQ客户端。
4. 导入原桥接配置，保留模型、多模态、记忆、工作区和会话映射。管理配置由修订号保护，连接变更需要显式重连。将原独立桥接设为不自启。
5. 给DSH服务的子进程精确开放必要的QQ状态、报告和工作区日记/技能目录。只传递指定视觉渠道需要的凭据环境变量；不继承任意密钥或NODE_OPTIONS。
6. 验证QQ在线、3类授权边界、业务数据/人格不变、定时任务、现有服务，以及匿名/agent访问管理接口被拒绝。真实QQ测试消息需要另行获得具体目标与内容授权。

回退顺序：先关闭新插件推理和发送并停工作进程，再恢复旧profile和旧消费者；保留迁移后的业务数据，禁止自动删除聊天、记忆或日记。不确定的发送不得自动重试。不要为回退重启无关QQ网关或其他服务。

日记可在管理页读取/下载，或由主人在私聊明确索取。群分析历史提供受授权的HTML下载，固定日期与群目录，撤销白名单后立即不可读取。没有生成文件时如实返回不存在。
